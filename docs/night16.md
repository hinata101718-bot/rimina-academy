依頼者：ヒナタさん（作業中はテストプレイをしています。返事はできません）

## 0. いちばん大事なこと
1. **質問で止まらないこと。** 迷ったら `docs/feedback.md` → `docs/design.md` → `docs/hearing.md` の順に意図を読み、判断して進め、判断を報告書に書く。物差し：このゲームの芯は「手応え」と「発見」。今回は**戦いを「見ているだけ」から「自分で読んで札を出す」へ**。
2. **①〜⑦をすべて終えるまで作業を続けること。時間の制限はない。** 大きな作り直しなので、段階ごとに公開しても遊べる順番で進める（新しい戦いが完成するまでは、今の戦いのまま遊べるように。切り替えは最後に）。
3. 段階ごとに `npm test` と `npm run build` を通してコミット・プッシュ。
4. **既存のセーブデータを壊さない。** 15夜目版（形式15）のセーブ（ふつう・戦闘の途中・3部隊の途中・結果の途中）のテストを足す。**戦闘の途中のセーブ**は、その戦いを新しい形でやり直すか、結果だけ出して進める（判断を報告書に）。
5. **シミュレーション**：戦いの中身がまるごと変わるので、オートプレイが札を出す仕組み（方針ごと）を作り、CLAUDE.md の「時間を短くする決まり」で、最後に長いシミュレーション（40年×10回×方針4つ）。`docs/sim-baseline.json`（15夜目）と比べて、在学中の戦死・勝率・お金・エンディング・宿敵・卒業時Lvが大きく崩れないこと。調整は2回まで。
6. iPhone の Safari を考える：画面の絵を読み取る計算はしない、タップ対象44px以上、幅360〜430px、上下に固定したボタンがずれない。札は小さくなりすぎないこと（文字12px以上）。
7. 言葉は `docs/writing-style.md`、見た目は「教官の机 × 軍記もの」。

## 2. 作るもの（この順番で）
### ① 生徒ごとに覚える技・魔法・スキル（feedback「生徒ごとに覚える技…」）
- 技能×ランクごとに3〜5通りの候補、入学のときに覚える表、決め方（性格・夢・国の流派・得意・家柄）、開花の固有の技、ランクが上がると札が強くなる、古いセーブの変換
- **条件で効くスキル**（HPが半分以下のとき・仲間が倒れたとき・先に攻撃したとき など）を候補に混ぜる（15夜目の残り）
### ② 札の戦いの仕組み（`src/core/`。DOMに依存しない・シード付き）
- 山札・手札5枚・行動力3・敵の次の行動の予告・4〜6ターン・前列後列・相性と弱点・策の札（地形と天候）・信頼で言うことを聞く・倒れた子の札・必殺（大当たり）・宿命の対決
- 敵の札（敵将の得意な戦技・「〇〇の使い手」）も同じ仕組みで
- オートプレイが札を出す（方針ごと。小さな依頼・同行しない部隊・シミュレーションで使う）
### ③ 画面（見本どおり）
- 出撃前の山札、札を出す画面（敵の予告・味方の窓・手札・行動力・「この〇枚を出す」・「おまかせで札を出す」）、札の結果（文の窓。結果の4段の決まりとむごい描写の決まり）、見せ場の演出
- 小さな依頼と同行しない部隊は結果だけ
### ④ つなぎ直し
- 部隊・部隊長・策を立てる子・ここぞの判断・評価（名場面は出した札から）・戦利品・抜擢・組織図・宿敵・年鑑・振り返り・新聞を、新しい戦いにつなぐ
### ⑤ 文の決まり（feedback「『串刺し』なのに生きている」）
- 攻撃のあとの結果で4段（ふつう・深手・重傷・死）、死ぬ段の言葉は死だけ、点検で0件
### ⑥ 切り替えと片づけ
- 新しい戦いに切り替える。古いマス目の戦いと、手で動かす戦闘の設定は、使わなくなった部分を片づける（セーブの変換に要るものは残す）
### ⑦ 仕上げ
- 長いシミュレーション、1か月の操作の数（授業20日＋月末の1部隊・3部隊）を15夜目と比べる、撮影は最後にまとめて1回（`docs/screenshots/night16/`）
