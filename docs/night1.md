## 0. いちばん大事なこと

1. **質問で止まらないこと。** 依頼者は朝まで返事ができません。仕様が曖昧なところは `docs/design.md` → `docs/hearing.md` の順に意図を読み取り、最も妥当な判断をして進め、その判断を `docs/reports/night1.md` の「判断したこと」に書く。
2. **このファイルの①〜⑥をすべて終えるまで作業を続けること。** 区切りのいいところで止まって報告しない。1つの段階が終わったら、すぐ次の段階に進む。
3. **段階ごとに「テスト→コミット→プッシュ」。** 後半で何かを壊しても、前の段階に戻れるようにする。
4. **詰まったら後回し。** 30分以上進まない機能は、最小限の仮実装（または未実装）にして次へ進み、報告に「未完成」として残す。
5. **①〜④は「遊べる品質」、⑤⑥は「動けばよい」でもかまわない。** ただし①〜⑥すべてで、ゲームが途中で止まったりセーブが壊れたりしないこと。
6. 数値はすべて `src/data/` のデータに置き、コードに直接書かない。

## 2. 作る順番と完成条件

### ① 土台
- Vite＋TypeScript のプロジェクト作成、`npm run dev` / `npm run build` / `npm test` / `npm run sim` が動く
- GitHub Actions：`main` へのプッシュで GitHub Pages に公開するワークフロー（`.github/workflows/deploy.yml`）。Viteの `base` は `/rimina-academy/`
- PWA（manifest、アイコン、サービスワーカー）、iPhoneの「ホーム画面に追加」の案内
- 画面の枠：下の5タブ（学校・生徒・戦況・年鑑・設定）、色合いの3段階切り替え（design §16.1）
- 状態管理・シード付き乱数・セーブ（IndexedDB＋書き出し/読み込み、セーブ枠3つ、バージョン番号）
- 生徒の自動生成（design §3：能力・成長率・技能・性格・夢・出身・特徴タグ・隠れた才能・名前）
- SVG似顔絵（パーツ組み合わせ）＋顔画像への差し替え口（`public/faces/`）
- オープニング（design §10.2）：教官の名前・経歴→着任→一期生と対面
- **完成条件**：新しいゲームを始めると、一期生6〜8人の名簿と個人ページが見られ、リロードしても状態が残る。書き出したファイルを読み込むと同じ状態に戻る

### ② 1週間
- 学年の重点科目2つ、生徒の目標技能2つ、授業による技能ポイントと経験値（design §6.1）
- 個人指導（技能指導／面談）、生徒からの相談（§6.2）
- 週末の交流：休養・お茶会・手合わせ・学年の食事会（§6.3）
- 疲労・やる気・体調不良（§3.4）、隠れた才能の判明度とヒント（§3.6）
- やること一覧、気にかける生徒、今月の主役、変化のお知らせ（§3.8, §16.3）
- 週のまとめ画面、「次の週へ」、未設定時の自動設定（§6.4）
- 支援値（生徒どうし）と信頼（教官へ）の増減（§7.1, §7.2）
- 支援会話：仕組み（話題×流れ×口調）と、話題を**最低8種**（夢、出身、特徴タグ、最近の出来事3種以上を含む）、10性格すべての口調（§7.3）
- 退学の予兆と面談による解消（§3.9）
- **完成条件**：1ヶ月（4週）をすべて手で操作して進められ、技能ランク・疲労・やる気・支援値・信頼が変化する。何も設定せずに「次の週へ」を押し続けても進む

### ③ 戦闘
- マップ（縦12×横8）、型を**最低3種**（森の街道、国境の村、訓練場）＋自動組み替え＋敵戦力の調整（§8.1）
- 地形・天候（§8.2, §8.3）、計算式・三すくみ・追撃・反撃・必殺（§8.4, §8.5）
- 武器（武器庫、出撃前の割り当て、初期の武器と購入）（§8.6）
- 兵種：見習いと初級6種・中級12種は完全に。上級以降もデータだけは全68種入れてよい（試験で到達できるのは中級まででよい）（§8.8）
- 移動・攻撃・回復・待機、戦闘予測、敵の攻撃範囲表示（§8.16）
- 敵AI（突撃・待ち伏せ・拠点防衛、優先順位）（§8.11）
- 勝利条件：全滅・ボス撃破・指定ターン防衛・護衛は必須、残りは可能なら（§8.12）
- 支援の戦闘効果（§7.1）、教官の指示3種（§8.9）
- 戦死と重傷、演習は死なない（§8.13）、巻き戻し（§8.14）
- 経験値・レベルアップ（§8.15）、講評
- 演出：数値ポップ＋簡易カットイン（初期設定は必殺・撃破・ボスのみ）、敵ターン速度とスキップ（§8.16）
- 戦闘中のターンごとの自動セーブ
- **完成条件**：演習と実戦をそれぞれ最後まで遊べ、勝敗・経験値・戦死/重傷が反映される。iPhoneの縦画面（幅390px想定）で全マスがタップできる

### ④ 1年
- 月末の依頼掲示板（演習1＋実戦2〜3）、報酬、評判、友好度（§9）
- 兵種試験（初級・中級）（§8.8）
- 施設・講師（雇う講師）・お金（§5）
- 年間行事：入学試験、夏の合宿、公開演武会、収穫祭、卒業試験・卒業式＋卒業写真（§2.2, §10）
- 進路（声かけ・希望・推薦の三者）（§10.3）
- 効果音（§16.6）
- **完成条件**：4月から3月まで通しで遊べ、卒業式で一期生（初年度は1学年しかいないので、テスト用に「3年生として開始」するデバッグ機能を用意してよい）が進路を決めて巣立つ

### ⑤ 年またぎ
- 年度末処理（§2.3）：学年の進級、3学年の在籍、入学試験
- 卒業生の毎年のシミュレーション（レベル・役職・出来事）、個人ページ（§11）
- 新聞（§16.5）と郵便受け（手紙は簡単なテンプレートでよい）
- 年鑑：卒業生名簿・卒業写真・年表（記録と家系は簡易でよい）（§13）
- 廃校期限の判定と傘下化（§5.5）
- **完成条件**：3年以上続けて遊べ、卒業生が年鑑と新聞に現れる

### ⑥ 戦況の基本
- 国力・関係・緊張度・学校との友好度、毎月と年度末の変動（§12.1〜12.3）
- 戦況タブの表示、緊張度による色合いの切り替え
- 大事件を**最低3本**：銃の登場、国境紛争、帝国の侵攻（できれば和平会議も）
- 卒業生が戦場に現れる（援軍か敵）を、可能なら簡易に
- **長期シミュレーション**：オートプレイで最低30年×10回まわし、`docs/sim-report.md` に結果（戦争の状況の推移、お金、評判、人数、エラーの有無）を書く。破綻（お金が永遠に0、評判が上がらない、エラー）があれば数値を調整
- **完成条件**：戦況が年ごとに動き、色合いが変わり、大事件が起きる。シミュレーションでエラーが出ない

### 報告書の形式（`docs/reports/night1.md`）
```
# 1夜目の報告
## できたこと（①〜⑥ごとに、完成／一部／未着手）
## 遊び方（朝ヒナタさんが最初にやること、3〜5行）
## 未完成のもの・既知の不具合
## 判断したこと（設計書にない・曖昧だったところで決めたこと）
## 長期シミュレーションの結果（要点）
## 遊んだあとに見てほしいポイント（手触り・バランスで確認してほしいこと）
## 2夜目への申し送り
```
文章はやさしい日本語で。専門用語は避ける（ヒナタさんはエンジニアではありません）。
